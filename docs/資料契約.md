# 法訊雷達共用資料契約 v1

> 供 A、B、C、D 共用的 MVP 資料格式。B 用於個人化排序，C 用於來源核對與問答，D 用於通知匹配；A 負責欄位與跨模組變更。示例中的租屋法案是虛構資料，不是法律資訊。

## 首版使用情境與範圍

**主要情境：** 一位租屋中的大學生，同時關注租屋權益與學生打工。使用者在 Web 選擇關注標籤後，首頁用推薦理由顯示可能相關的法訊；使用者開啟官方來源確認資料，再問「這是提案還是已經生效？」。問答只引用已核對來源，分開說明立法院進度與法規施行狀態；若沒有足夠來源，明確說無法確認。符合標籤、重要程度與通知同意的更新，才透過連結的 LINE 官方帳號傳給該使用者。

**MVP 展示範圍：** 以一筆共用 NewsItem 串起首頁、來源問答和 LINE 通知；先用可核對的官方來源及單一受控測試帳號。正式個案法律意見、多使用者群發和未核對資料的自動推播不在首版範圍。

**完成判準：** B、C、D 都能依 v1.0.1 和唯一 fixture 開始開發；同一筆資料在首頁、問答與通知中保持相同標題、狀態和來源；三讀不顯示為生效；來源不足時不給確定法律結論、不發實際通知。

## 使用規則

1. 每筆記錄都要保留可追溯的來源與來源核對狀態。
2. 只有 `verificationStatus = "verified"` 且有有效 `source.url` 的記錄，才可用於法律答案或通知事實。未核對資料可供介面測試，但必須標示示意。
3. 不知道的日期、進度或狀態用 `null`／`unknown`；不推測、不把空值補成今天。
4. 摘要只能整理來源支持的內容。法律狀態標籤以結構化欄位為準，AI 不得從摘要推算生效狀態。
5. 時間戳用 ISO 8601 並包含時區；只有日期的欄位用 `YYYY-MM-DD`。

## 版本與共用 Fixture

- 契約版本：1.0.1；新增可選 source.publishedDate，保存來源僅提供日期精度的公布資訊；原有欄位與 enum 維持相容。不相容變更提高主版本並先更新 Issue #1。
- 唯一共用 fixture：`data/fixtures/news-items.v1.json`，外層為 `{ "schemaVersion": "1.0.1", "items": [...] }`。
- B、C、D 都從這個位置讀取資料；不要各自複製一份不同欄位的法訊。B 可用 `pending` 記錄測 UI，C 將逐筆核對後的真實資料加進同一份 fixture。
- `pending` 的假資料只能用於介面測試，不可用於法律事實問答或實際 LINE 推播。

## NewsItem 欄位

| 欄位 | 型別 | 必填 | 用途／規則 |
|---|---|---:|---|
| `id` | string | 是 | 唯一識別碼；優先沿用官方資料識別碼，沒有時由匯入流程產生穩定 ID。 |
| `recordType` | enum | 是 | `bill`、`meeting`、`regulation`、`official_notice`。 |
| `title` | string | 是 | 官方文件或議案標題；改寫的標題需保留原始標題於 source。 |
| `summary` | string | 是 | 供首頁顯示的短摘要，只能寫來源可支持的事實；資料不足時說明尚待確認。 |
| `topicTags` | string[] | 是 | 議題標籤，如「租屋權益」「勞動保障」；無標籤用空陣列。 |
| `audienceTags` | string[] | 是 | 可能相關的生活身分，如「租屋族」「學生打工」；代表資訊關聯，不代表法律適用結論。 |
| `billStage` | enum \| null | 是 | 法案在立法院的審議階段；非法律案用 `null`。見下方狀態表。 |
| `legalEffect` | enum \| null | 是 | 法規公布／施行狀態；不是法律效力資料的記錄用 `null`。不可由三讀直接推定為生效。 |
| `sourceStatusText` | string \| null | 是 | 來源原文中的進度文字；無法找到時為 `null`。 |
| `meetingStatus` | enum \| null | 是 | 會議狀態；非會議記錄用 `null`。 |
| `publishedAt` | datetime \| null | 是 | 來源發布時間；未知為 `null`。 |
| `updatedAt` | datetime \| null | 是 | 來源所示更新時間；未知為 `null`。 |
| `meetingDate` | date \| null | 是 | 會議日期；非會議或未定日期為 `null`。 |
| `source` | object | 是 | 原始來源識別與連結；欄位見下表。 |
| `sourceExcerpt` | string \| null | 是 | 支持摘要／回答的短原文或段落定位；沒有可引用內容時為 `null`。 |
| `verificationStatus` | enum | 是 | `pending`、`verified`、`needs_review`。只有 `verified` 可供問答或通知引用。 |
| `verifiedAt` | datetime \| null | 是 | 人工核對時間；未核對為 `null`。 |
| `verifiedBy` | string \| null | 是 | 核對成員代號 A–E；未核對為 `null`。 |
| `notificationLevel` | enum | 是 | `none` 或 `important`。表示資料層建議等級；是否真的發送仍須符合使用者偏好與同意。 |

### source 欄位

| 欄位 | 型別 | 必填 | 規則 |
|---|---|---:|---|
| `organization` | string | 是 | 發布機關／資料平台名稱；示意資料填「示意資料」。 |
| `documentTitle` | string \| null | 是 | 官方文件或資料集名稱；未知用 `null`。 |
| `url` | string \| null | 是 | 官方原始網址；不得填猜測或佔位網址。 |
| `publishedAt` | datetime \| null | 是 | 來源文件精確發布時間；若來源只列日期，使用 source.publishedDate。 |
| source.publishedDate | date | 否 | 官方來源只提供日期時填 YYYY-MM-DD；不補造時分；若法規資料庫顯示的是全法修正日期，於 citationLocator 標明。 |
| `accessedAt` | datetime \| null | 是 | 團隊最後開啟並核對來源的時間。 |
| `citationLocator` | string \| null | 是 | 條次、頁碼、議案編號或資料列識別；無法定位用 `null`。 |

## v1 標籤詞彙

- `topicTags` 首版值：`租屋權益`、`學生打工`、`勞動保障`。`學生打工` 是關注議題，`學生` 才是身分標籤。
- `audienceTags` 首版值：`租屋族`、`學生`。標籤代表可能相關的使用者群，不代表該法規必然適用該個人。
- 新增標籤前，在 #1 記錄名稱、用途和能支持該標籤的來源依據，避免同義詞分裂成多個值。

## 狀態值與使用方式

### billStage：立法院審議階段

| 值 | 顯示方式 | 含義 |
|---|---|---|
| `proposed` | 已提出 | 來源顯示已提案；不代表已完成審查。 |
| `first_reading` | 一讀／交付審查 | 來源明確記錄一讀或交付委員會。 |
| `committee_review` | 委員會審查 | 仍在委員會審查中。 |
| `party_negotiation` | 黨團協商 | 來源明確記錄進入協商。 |
| `second_reading` | 二讀 | 來源明確記錄進入二讀程序。 |
| `third_reading_passed` | 三讀通過 | 只代表立法院完成三讀；**不可顯示為已公布或已生效**。 |
| `executive_reconsideration` | 覆議程序 | 來源明確記錄行政院移請覆議；細節放 `sourceStatusText`。 |
| `legislative_reconsideration` | 復議程序 | 來源明確記錄立法院對議案提出復議；細節放 `sourceStatusText`。 |
| `rejected` | 未通過／不予審議 | 官方紀錄明確標示未通過或不予審議。 |
| `withdrawn` | 撤回 | 官方紀錄明確標示撤回。 |
| `unknown` | 狀態待核 | 找不到足夠來源確認目前階段。 |

### legalEffect：公布與施行狀態

| 值 | 顯示方式 | 含義 |
|---|---|---|
| `not_promulgated` | 尚未公布 | 已有相關議案，但來源未證明完成公布。 |
| `promulgated_effective_date_pending` | 已公布，施行日待確認 | 有公布來源，尚未確認生效日期／條件。 |
| `effective` | 已施行 | 官方法規資料能確認已到施行日。 |
| `repealed_or_expired` | 已廢止／失效 | 官方資料明確標示廢止或失效。 |
| `unknown` | 效力待核 | 找不到足夠來源確認公布或施行狀態。 |
| `not_applicable` | 不適用 | 僅用於明確沒有法律效力狀態的記錄；一般非法律記錄的欄位應用 `null`。 |

立法院 FAQ 說明法律案三讀後仍須移送並經總統公布；公布後是否立即生效，還要看法規所定施行日期。因此 `billStage` 和 `legalEffect` 分開存，不以「三讀通過」代替「已生效」。參考：[立法院：三讀條文是否立即生效](https://www.ly.gov.tw/Pages/Detail.aspx?nodeid=217&pid=37536)、[中央法規標準法第 12–14 條](https://law.moj.gov.tw/LawClass/LawAll.aspx?PCode=A0030133)。

### meetingStatus：會議狀態

允許值：`scheduled`（已排定）、`held`（已舉行）、`postponed`（延期）、`cancelled`（取消）、`unknown`（待核）。狀態須有議程／會議紀錄支持；僅有新聞摘要時先標 `unknown`。

## 問答與通知的過濾條件

- 問答可引用的記錄：`verificationStatus = "verified"`、`source.url` 非空，且 `sourceExcerpt` 或可定位的 `citationLocator` 非空。
- 問答需回答法案進度時，同時讀取 `billStage` 與 `legalEffect`；若其中一項 `unknown`，分開說明已確認與未確認部分。
- LINE 通知只處理 `verificationStatus = "verified"`、`notificationLevel = "important"` 的記錄，之後再比對使用者的 `topicTags`／`audienceTags` 偏好、通知同意和停用設定。
- 標籤匹配只表示可能相關，通知與回答都不能把標籤當作個案法律適用判斷。

```json
  "title": "示意法訊：租屋相關提案（虛構）",
  "summary": "此筆僅測試欄位呈現，不代表真實提案或法律資訊。",
  "topicTags": ["租屋權益"],
  "audienceTags": ["租屋族", "學生"],
"billStage": "unknown",
  "legalEffect": "unknown",
  "sourceStatusText": null,
  "meetingStatus": null,
  "publishedAt": null,
  "updatedAt": null,
  "meetingDate": null,
  "source": {
    "organization": "示意資料",
    "documentTitle": null,
    "url": null,
    "publishedAt": null,
    "accessedAt": null,
    "citationLocator": null
  },
  "sourceExcerpt": null,
  "verificationStatus": "pending",
  "verifiedAt": null,
  "verifiedBy": null,
  "notificationLevel": "none"
}
```

共用 fixture 的檔案外層格式如下，`items` 陣列中的物件遵循上方 `NewsItem` 欄位定義：

```json
{
  "schemaVersion": "1.0.1",
  "items": []
}
```
