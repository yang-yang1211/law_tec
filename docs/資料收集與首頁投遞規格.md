# 自動收集與首頁投遞規格

## 目的與邊界

將「找到官方資料 → 篩選來源 → 分類與標籤建議 → 產生首頁短標題 → 配對使用者 → 顯示在首頁」整理成可實作流程。

本文把「投遞到首頁」定義為登入後出現在個人化 feed；不包含瀏覽器推播或 LINE Push。LINE 通知仍由 D 的獨立流程處理。自動化可以擷取和整理候選資料，但不能自行把未核對內容標成已核實。

目前原型沒有連接官方來源 API、RSS 或排程服務。本文定義 MVP 規則與驗收條件，不代表已開始自動抓取。

## 流程總覽

1. 從已登錄的官方來源取得更新，保留原始網址、機關、文件標題、公布／更新日期和來源識別碼。
2. 檢查來源主機、文件類型、日期、引用位置、相關性和重複項。
3. 對通過來源檢查的候選，提出 NewsItem 類型、主題標籤、身分標籤和首頁短標題。
4. 將候選和自動化依據放進待審佇列，不直接寫成 verified。
5. C 核對來源事實、法律／議事狀態、標籤和短標題；核對完成後才建立或更新共用 NewsItem。
6. 首頁依使用者偏好標籤配對已核對資料，產生個人化 FeedCard，並使用 B 的排序規則顯示。
7. 使用者開啟卡片時可看到正式資料標題、摘要、日期、法律狀態及官方原始來源。

## 來源登錄與篩選

### 首版來源主機白名單

只自動讀取已逐一登錄的 HTTPS 官方來源主機。MVP 初始清單：

| 主機 | 資料用途 |
|---|---|
| law.moj.gov.tw、gazette.nat.gov.tw | 現行法規、法規命令與正式公告 |
| ly.gov.tw、data.ly.gov.tw | 立法院議案、議程、會議與議事資料 |
| moi.gov.tw、nlma.gov.tw、pip.moi.gov.tw、ws.moi.gov.tw | 住宅政策、租屋規則與租金補貼 |
| mof.gov.tw、dot.gov.tw | 租屋相關稅務規定與申報說明 |

以精確主機名稱比對，不自動放行整個 gov.tw 網域。要加入地方政府或其他官方網站，先登錄主機、資料用途、更新方式和引用格式，再由 A 與 C 確認。搜尋結果頁、社群貼文、私人部落格及媒體文章不能作為自動發布來源。

每個來源登錄項目至少記錄：來源識別碼、官方機關、精確主機、資料類型、API／RSS／清單頁方式、更新頻率、可收錄議題、來源使用限制、負責人與最近成功讀取時間。若網站使用條款或自動讀取方式尚未確認，先以人工提供官方連結方式收集，不啟動排程抓取。

### 篩選規則

一筆候選只有同時符合以下條件，才通過自動來源檢查並進入待審佇列：

- HTTPS 網址主機符合已核准白名單，最後落地網址仍在核准來源內。
- 網址指向官方文件或正式內容頁，不是搜尋結果、首頁或無法定位的附件清單。
- 能取得機關、正式標題、官方 URL，以及公布日期或更新日期；來源只提供日期時使用 source.publishedDate，不補造時分。
- 有條次、公告文號、議案編號、資料列 ID 或其他 citationLocator；並保留支持摘要的短摘錄。
- 內容符合租屋權益、學生打工或勞動保障等已定義議題。
- 依標準化網址、官方文件 ID、標題及公布日期檢查重複；同一文件更新時更新既有候選，不另建重複資料。

來源結果分為三種：

- **通過待審：**來源與文件可回查、議題相符、未發現重複。
- **人工複核：**日期缺漏、狀態不明、來源改版、文字辨識品質差、來源內容互相矛盾或文件是否仍有效不確定。
- **排除：**非核准來源、明顯離題、無法回到原始資料或重複且沒有新內容。

來源分級：

- **A 級原始資料：**法規原文、行政院公報、立法院正式議案／議事資料、主管機關正式公告。可作為法律或議事事實的主要引用依據。
- **B 級官方說明：**主管機關 FAQ、政策說明或新聞稿。可說明申請方式、政策期間或行政流程；法律效力仍須以法規原文或正式公告核對。
- **C 級非官方資訊：**媒體、社群和私人網站。僅可作為發現候選議題的線索，不可自動收錄、用於法律問答或首頁事實敘述。

## 類型與標籤建議

recordType 依文件性質判斷：法規為 regulation、主管機關政策／福利公告為 official_notice、立法院法案為 bill、會議或議程為 meeting。來源類型可提供預設值，文字分類只能提出建議。

topicTags 和 audienceTags 只使用資料契約的受控詞彙。首版 topicTags 為租屋權益、學生打工、勞動保障；audienceTags 為租屋族、學生。分類結果須附上命中的來源詞句或段落，不能只靠主機名稱推論。分類器信心低於 0.85、沒有可指出的文字依據，或議題／身分無法區分時，標記 needs_review，不自動配對使用者。

標籤表示內容可能相關，不代表法律適用或補助資格。補助資格仍以官方條件和個人審查結果為準。

## 首頁短標題

正式 NewsItem.title 保留官方文件標題。自動化產生的 feedTitle 是首頁呈現用的短標題，屬於 FeedCard 投影，不覆寫共用資料的正式標題。卡片仍保留正式標題、摘要、來源、日期和法律狀態，方便使用者回查。

短標題規則：

- 建議 8 至 28 個中文字，直述誰做了什麼或權益重點。
- 只能使用官方來源支持的主體、行動、金額、日期和條件；不得把提案寫成生效法規，也不得省略「符合條件者」等重要限制。
- 不使用誇大、恐嚇、保證資格或個案法律結論。
- 保留官方來源連結；原標題與 feedTitle 必須可並列檢視。
- 標題草稿信心低於 0.85、超出字數或可能改變法律意義時，交人工修訂。

目前五筆資料的短標題示例：

| 正式資料 | 首頁短標題草稿 |
|---|---|
| 土地法第99條押租金規定 | 租屋押金最多收兩個月租金 |
| 民法第429、430條修繕規定 | 房屋修繕原則由房東負責 |
| 租約不得禁止申請租金補貼 | 租約不能禁止申請租金補貼 |
| 115年度租金補貼計畫 | 115年度租金補貼受理至年底 |
| 房屋租金支出特別扣除額 | 符合條件者租金年扣除上限18萬元 |

## 標籤配對與首頁顯示

配對在讀取首頁時依個人偏好計算，不把使用者 ID 寫入共用 NewsItem。FeedCard 最少包含 newsItemId、feedTitle、matchedTags、推薦理由和來源連結。topicTags 或 audienceTags 至少命中一個使用者偏好，才出現在「為你推薦」或「我追蹤的」；依 B 的排序規則排列。沒有個人標籤命中的已核對資料，可依首頁既有規則出現在「最新消息」。

正式首頁只顯示同時符合以下條件的資料：

- verificationStatus 為 verified。
- source.url 有效，且有 sourceExcerpt 或可定位的 citationLocator。
- 類型、狀態和短標題已經 C 核對；狀態未知時明確顯示未知，不補猜。
- 若來源已被更新、撤回或廢止，依官方資料調整或下架首頁排序。

pending 和 needs_review 候選只在待審工具或明確標示的測試畫面出現，不進正式個人首頁。通過標籤配對也不能略過來源核對。

## 候選佇列與人工責任

待審項目需保留 sourceFilterResult、sourceTier、建議 recordType、建議標籤、feedTitle 草稿、分類／標題信心、依據句、重複檢查結果、reviewReason、取得時間和流程狀態。它是內部候選紀錄，不替代共用 NewsItem。

流程狀態依序為 discovered、source_checked、classified、headline_drafted、needs_review、verified/published；不合格候選記為 rejected。自動化不得自行把 verificationStatus 設為 verified，也不得自行把 notificationLevel 設為 important。C 對官方來源和法律／議事狀態負責；A 維護來源清單與共用流程；B 顯示已核對的 FeedCard；E 抽查標題、標籤和來源。LINE 發送仍依 D 的同意、偏好、帳號狀態和重要程度條件處理。

## MVP 驗收與分階段實作

- 給定核准來源頁，能產生來源欄位完整的待審項目，並留下檢查依據。
- 非白名單來源、搜尋結果頁和重複文件不會自動進入待審後的正式 feed。
- 日期或法律狀態不清楚、分類／標題信心低於 0.85 的項目會停在 needs_review。
- 至少用租屋族與學生兩種標籤設定，確認命中項目出現在對應首頁，未命中項目不進「為你推薦」。
- 待審資料不會出現在正式首頁，也不會觸發 LINE API。
- 首先用現有 fixture 和人工提供的官方 URL 驗證篩選、標籤及短標題流程；再選定一個官方 API 或 RSS 接入。來源格式和頻率核對完成前，不啟動廣泛網頁爬取。
