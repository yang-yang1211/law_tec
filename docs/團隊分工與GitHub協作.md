## 共用資料契約

跨模組使用 [NewsItem 資料契約 v1.0.0](資料契約.md)，唯一共用 fixture 為 `data/fixtures/news-items.v1.json`。B、C、D 不另建不同欄位的資料副本；新增欄位先在 Issue 提出並由 A 確認。只有已核對且來源可回查的資料可用於法律事實問答或實際 LINE 推播。

## 分支、PR 與 Review

1. `main` 保持可展示；不要直接推送到 `main`。
2. 一張 Issue 對應一個分支，例如 `feat/p-02-personal-feed`。
3. PR 標題含 Issue 數字編號，描述用 `Closes #<數字>` 連回 Issue。
4. PR 至少附上改動摘要、畫面截圖或 Demo 步驟、驗收結果、資料來源和已知限制。
5. 主要負責成員之外至少一人 Review；跨模組 PR 由 A 確認整合介面。
6. 合併後由負責人更新 Project 狀態，並在 Issue 註明驗收結果。
7. API 金鑰、LINE channel secret/token、個人資料或測試帳號密碼不得提交到 GitHub；用環境設定，提交不含秘密的 `.env.example`。

## 每日非同步同步

每位成員在自己負責的 Issue 留三行短更新：

```text
昨天完成：
今天要完成：
卡住／需要誰協助：
```

遇到阻塞，在 Issue 標記 `Blocked` 並通知相關負責角色。
