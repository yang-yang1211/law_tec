# 法訊雷達：個人化法律資訊助手

> 2026「NextWave：AI 法創黑客松」計畫書草案。此文件先以 Markdown 協作，內容可再整理成競賽要求的書面計畫與簡報。原型中的消息、會議、帳號連結狀態均為示意資料。

## 一、計畫摘要

法訊雷達是一項以網頁為主要入口的個人化法律資訊服務。使用者自選關注身分與議題，系統將立法院公開議事資料與官方法規資料整理成容易理解的資訊流，並標示法案狀態、資料日期、推薦原因及來源。使用者可連結 LINE 官方帳號，接收符合關注條件的重要進度提醒；遇到疑問時，則可使用附引用資料的 AI 問答功能。

本計畫首版聚焦租屋學生與學生打工族，示範如何把「找到消息、理解法律狀態、收到個人提醒、回查官方來源」串成一段完整體驗。服務提供法律資訊整理與來源導引，不取代律師或法律扶助服務。

## 二、問題定義與背景

民眾遇到租屋、打工或其他日常法律問題時，常需要自行搜尋分散在法規網站、新聞與立法院網站的資料。法案提案、委員會審查、三讀通過與施行時間容易被混淆；長篇法規與議事資料也提高了理解門檻。即使某項法律變動可能影響自身權益，使用者仍要主動追蹤多個網站，才能知道最新進度與消息來源。一般新聞資訊多以主題或熱度呈現，較少說明「這和我的生活有什麼關係」。租屋學生與學生打工族尤其缺乏持續追蹤法規和立法院議程的時間。法訊雷達將官方資料、個人關注與淺白摘要整合於網頁首頁，並以 LINE 傳送重要更新，降低法律資訊的搜尋和理解成本。

### 目標使用者

- **主要使用者**：18 歲以上大專院校學生，尤其是租屋或有打工經驗者。
- **延伸使用者**：接案工作者、一般勞工、小型商家及其他希望追蹤特定法律議題的民眾。
- **首版關注標籤**：租屋族、學生打工；之後可依資料品質與使用者回饋擴充。

### 核心需求

1. 知道近期哪些法律與立法院消息可能和自己有關。
2. 分清提案、審議中、通過、公布與施行等不同狀態。
3. 不必每天自行查網站，也能收到重要進度提醒。
4. 對 AI 回答能回到原始官方資料核對。

## 三、解決方案與使用流程

### 使用流程

1. 使用者在網頁選擇關注身分與議題，並設定是否接收 LINE 通知。
2. 首頁依關注標籤、近期互動、議題進度與時間性排列消息。
3. 每則推薦內容標示「推薦原因」、法案或會議狀態、更新日期與官方來源。
4. 使用者可切換「為你推薦、我追蹤的、最新消息」，或調整關注內容。
5. 符合通知偏好的重要進度，透過已連結的 LINE 官方帳號送達使用者。
6. 聊天機器人依已收錄資料回答問題，附來源；資料不足時明確表示無法確認。

### 功能範圍

#### 1. 個人化首頁推薦

使用者自選的身分和議題是主要推薦訊號；近期法案狀態、會議時間與資料新近程度用來判斷資訊時效；追蹤、收藏及「少推薦這類」回饋用來調整興趣排序。每則卡片說明推薦理由，並保留「我追蹤的」與「最新消息」檢視方式，方便使用者自行掌握排序邏輯。

#### 2. 立法院會議與法案資訊

呈現相關議程、會議摘要及法案進度。畫面明確區分提案、審議、三讀、公布與施行資訊，並保留原始資料連結。立法院開放資料平台提供議事、會議及其他類資料，並提供 API 與多種交換格式；團隊會先選定適合首版的資料集，再逐一確認欄位、更新頻率和授權條款。[立法院開放資料開發指南](https://data.ly.gov.tw/odw/developer.action)；[立法院資料目錄](https://data.ly.gov.tw/catelog.action)

#### 3. LINE 個人通知

網站保留使用者的關注偏好，並讓使用者將網站帳號與 LINE 帳號連結。使用者需先加入官方帳號好友並完成帳號連結；當追蹤議題出現重要且已確認的進度時，系統依該使用者的偏好發送通知。訊息包含變動摘要、法案狀態、更新時間與官方資料連結。LINE Messaging API 文件提供服務帳號連結流程與推送訊息功能；正式實作會依官方流程處理驗證、通知同意與解除連結。[LINE 帳號連結](https://developers.line.biz/en/docs/messaging-api/linking-accounts/)；[LINE 傳送訊息](https://developers.line.biz/en/docs/messaging-api/sending-messages/)

#### 4. 有來源依據的 AI 問答

聊天機器人從核對過的官方法規與立法院資料中檢索，再用淺白文字整理答案。回答卡片呈現資料標題、來源、更新時間及法案狀態；使用者可以開啟原始資料。法規文本以法務部全國法規資料庫為優先來源，並同步保留法規版本及生效狀態欄位。[全國法規資料庫](https://law.moj.gov.tw/)

## 四、AI 使用方式與準確性設計

AI 用於四個範圍：議題分類、與使用者標籤的關聯判斷、官方資料的淺白摘要、依來源檢索的問答。AI 不自行判定法規效力，也不以生成內容取代來源文本。

### 回答與摘要的基本規則

- 只從已收錄且可回查的官方或經團隊核對來源產生法律事實摘要。
- 回答要區分現行法規、尚未生效條文與審議中的提案。
- 附上來源名稱、資料日期、原始連結及法案狀態。
- 檢索不到足夠依據時，說明資料不足並停止推論。
- 不提供個案法律結論；引導使用者查看原始資料或尋求正式法律服務。

### MVP 驗收指標（建議值）

- 建立至少 20 題由團隊整理的常見問題，逐題記錄參考來源與標準重點。
- 每個法律答案均有可開啟的來源；未引用來源的答案不通過驗收。
- 在測試題中檢查法案狀態、有效日期、引用對應性及無依據時的拒答表現。
- 每則推薦卡片均顯示推薦原因；使用者可以切換追蹤與最新排序。
- LINE 通知只由已核對的資料更新觸發，並能在網站調整或停止通知。

以上是 MVP 驗收規則，不代表未經測試的準確率承諾。展示時會提供測試題、來源與結果摘要。

## 五、資料流程與技術架構

```text
立法院公開議事資料 ─┐
法務部法規資料     ─┴→ 資料整理與狀態標記 → AI 分類／摘要／檢索
                                              ├→ 個人化網頁資訊流
使用者關注與回饋 ────────────────────────┤
                                              ├→ 有來源的聊天問答
已連結 LINE 使用者與通知偏好 ───────────────→ LINE 重要更新通知
```

建議團隊共用一筆 `NewsItem` 資料格式，降低模組整合衝突：

| 欄位 | 說明 |
|---|---|
| `id` | 消息唯一識別碼 |
| `title` / `summary` | 標題與淺白摘要 |
| `topicTags` / `audienceTags` | 議題和可能相關身分 |
| `status` | 提案、審議、三讀、公布或施行等狀態 |
| `publishedAt` / `updatedAt` | 發布與資料更新時間 |
| `sourceName` / `sourceUrl` | 官方來源名稱和原始連結 |
| `meetingDate` | 相關會議日期；沒有時留空 |
| `notificationLevel` | 是否符合重要通知門檻及原因 |

原型初期以少量核對過的示例資料完成整段展示；確認資料欄位和更新流程後，再擴充自動介接。資料集實際欄位和更新時間以各官方資料集說明為準。

## 六、個資、信任與風險控制

- 使用者以自選關注標籤建立個人化，不要求提供身分證字號或案件細節。
- 個人化通知採明確同意；讓使用者知道可調整偏好及解除 LINE 帳號連結。
- LINE 官方文件要求帳號連結設計提供解除連結方式，並在連結時告知使用者。[LINE 帳號連結規範](https://developers.line.biz/en/docs/messaging-api/linking-accounts/)
- 使用來源時間戳與狀態標籤避免把討論中的提案呈現為已生效法律。
- AI 內容保留可追溯來源；法案狀態和日期由結構化資料優先決定。
- 任何不確定的摘要、錯誤分類或不完整資料，都應可由使用者回報並由團隊修正。

## 七、MVP 範圍與展示情境

### 首版交付

1. 一個響應式網頁首頁，包含關注標籤、推薦／追蹤／最新分頁與推薦理由。
2. 租屋權益及學生打工兩類示範內容，附官方來源、狀態和更新時間。
3. 立法院會議資訊區與法案進度卡片。
4. 一個有來源引用和拒答能力的問答流程。
5. 一段 LINE 帳號連結與重要更新通知的可操作或可視化展示。

### 決賽 Demo

以「租屋中的學生打工族」為情境：使用者選擇關注標籤，首頁推薦一則相關會議或法案進度，卡片顯示推薦原因及來源；使用者接著詢問聊天機器人「這是提案還是已經生效」，查看引用來源；最後展示重要進度如何依偏好送到 LINE。

## 八、五人團隊分工

| 代號 | 分工 | 主要工作 | 主要交付物 |
|---|---|---|---|
| A（你） | 整合規劃 | 需求範圍、共用資料格式、模組整合、進度、計畫書與簡報 | 可端到端展示的 MVP、計畫書與簡報主線 |
| B | 個人化推薦 | 關注標籤、排序規則、推薦理由、首頁 feed | 可切換推薦／追蹤／最新的首頁模組 |
| C | 法律資料與 AI 問答 | 官方資料整理、法案狀態、檢索問答、引用與拒答 | 可回查來源的資料集與問答流程 |
| D | LINE 通知 | LINE 帳號連結、通知偏好、重要更新推送 | 一個連結流程和一種個人通知情境 |
| E | 團隊支援與交付 | 整理示例資料、手動驗收、截圖與 Demo 腳本、會議記錄、文件排版 | 驗收清單、可重現 Demo 步驟、提交素材 |

B、C、D 各自負責一個核心模組，交付時同時說明設計取捨、資料來源、失敗情況和如何驗收，讓每位成員都能在成果簡報中解釋自己的部分。

## 十、評審對應與成果說明

- **問題聚焦與社會影響力**：以法律資訊不易搜尋、理解與追蹤為核心問題，聚焦租屋學生和學生打工族。
- **AI 應用與創新性**：以個人化排序、易讀摘要及來源檢索問答串起資料使用流程。
- **簡報表現**：用一個使用者情境完整演示資訊如何被發現、理解和追蹤。
- **未來可行性**：先以少量、可核對的官方資料完成 MVP，再依資料來源品質擴大議題範圍。

簡章初賽配分為企劃完整性 35%、創意性 30%、AI 應用整合性 25%、技術可執行性 10%；決賽配分為問題聚焦與社會影響力 35%、AI 技術應用與創新性 25%、簡報表現 20%、未來可行性 20%。本計畫因此同時呈現社會需求、AI 角色、來源可信度和可展示的原型。
