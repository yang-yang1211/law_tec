# C｜官方資料核對與引用式問答

**一句話目標：**逐筆核對少量官方法訊，再讓問答只使用已核對資料；沒有依據時清楚拒答。

## 負責 Issues

- [#3 整理並核對立法院與法規示例資料](https://github.com/yang-yang1211/law_tec/issues/3)
- [#4 建立有來源引用的法律問答與拒答流程](https://github.com/yang-yang1211/law_tec/issues/4)

## 工作邊界與輸入

- 使用 A 維護的資料契約 v1.0.0 和唯一共用 fixture `data/fixtures/news-items.v1.json`。
- 使用立法院、全國法規資料庫等可回查的官方來源；狀態不明、日期缺漏或來源衝突時保留未知並標待核。
- C 負責來源和法律／議事狀態正確性及問答依據；B 負責首頁排序，D 負責 LINE 連結和通知。

## Issue #3：資料整理與來源核對

1. 在共用 fixture 維護至少 6 筆租屋或勞動議題 NewsItem。
2. 每筆填官方來源 URL、文件名稱、發布／更新時間、查核時間、引用定位和支持摘要的原文摘錄。
3. 只有逐筆核對完成、來源可回查時才設 `verificationStatus=verified`；未知狀態不得靠標題或摘要推測。
4. 在 `docs/來源查核紀錄.md` 記錄資料集名稱、更新頻率／限制、每筆核對結果和未解問題。
5. 請 E 抽查至少 2 筆；由 C 處理錯誤並在 #3 記錄更正依據。

## Issue #4：引用式問答與拒答

1. 在 `prototype/qa.js` 實作 `answerQuestion(question, items)`，只檢索已核對且來源可回查的資料。
2. 回傳 `status`（`answered` 或 `insufficient_evidence`）、`answer`、`references`、`billStage` 和 `legalEffect`。
3. 每項回答事實都要附資料標題、官方 URL 和可定位段落；立法院審議狀態與法律公布／施行狀態分開呈現。
4. 沒有符合資料、來源衝突、狀態未知或問題要求個案法律判斷時，明確拒答，不補猜答案。
5. 在 `docs/問答測試案例.md` 寫至少 20 題，逐題列出預期回答／拒答、依據資料 ID 和引用；至少手動記錄 5 題實際結果。

## 完成條件

- 至少 6 筆資料的來源和狀態可逐筆重現；E 抽查問題已有處理結論。
- 問答只使用可引用的核對資料；不確定或缺資料時拒答。
- 20 題案例和至少 5 題實際結果包含問題、預期、實際、引用來源。
- 已把問答函式介面和限制交 A；讓 A 在 #7 接上聊天畫面。

## 交接

- 把核對完成的 fixture 交給 B 用於首頁、D 用於通知匹配。
- 把問答函式回傳格式、測試案例和限制交給 A 整合。
- E 抽查至少 2 筆來源和問答引用；C 修正自己的資料和答案。
