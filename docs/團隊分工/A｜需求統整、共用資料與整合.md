## 實際待辦

### 1. 收尾共用規格（#1）

- 資料契約 v1.0.1 已整理在 `docs/資料契約.md`，共用 fixture 固定為 `data/fixtures/news-items.v1.json`。
- 維護自動收集規格與精確來源主機白名單；新增主機由 A、C 確認用途、取得方式和引用條件。
- 請 B、C、D 確認欄位足以開發；請 E 確認可據以驗收。
- 新增或修改欄位時，記錄原因、空值規則、受影響模組和決定，不讓各模組各自改格式。

### 2. 串接整合版（#7）

- 接上 B 的推薦／追蹤／最新 feed、C 的引用問答、D 的通知流程。
- 所有模組讀取同一筆 NewsItem；首頁、問答和通知中的標題、狀態、日期、來源保持一致。
- LINE 有測試環境時，只推播到已確認的單一測試帳號；沒有環境時使用明確標示的模擬流程。
- 記錄模組介面、錯誤替代畫面、Demo 前置條件和整合問題，並指派回原模組負責人。

### 3. 完成 Pitch 與 Demo 腳本（#9）

- 主線依序說明：使用者問題 → 選擇關注 → 首頁推薦 → 查看官方來源 → 引用問答或拒答 → LINE 更新。
- B、C、D 各提供輸入、核心判斷、限制和驗收結果；E 協助整理截圖和計時。
- Pitch 控制在兩分鐘內；不能把示意畫面或未實測 API 說成已完成。

### 4. 完成書面資料與提交檢查（#10）

- 逐項對照簡章確認必交文件、格式、頁數、提交入口和正式期限。
- 整合計畫書、團隊介紹、分工、Prototype 和 Demo 素材；各模組內容由 B、C、D 提供。
- 與 E 抽查連結、檔案和影片；記下最後檢查時間及仍未完成事項。

## 完成條件

- 五人能使用同一份資料格式完成各自模組。
- 其他成員能照 Demo 腳本，從乾淨瀏覽器狀態重跑完整流程。
- 未完成或模擬的功能有清楚標示；Pitch 不超過兩分鐘。
- 提交清單每項都能對應簡章要求，連結和檔案可開啟。

## 交接

- 向 B、C、D 提供已確認的共用欄位和整合介面。
- 收到各模組的可展示切片、限制和驗收結果後負責整合。
- E 提供抽查結果、問題清單、截圖和檔案檢查結果；A 決定整合處理或 Demo 降級方式。
