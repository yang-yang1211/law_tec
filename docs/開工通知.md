# 法訊雷達團隊開工通知

以下內容可直接貼到團隊群組；請把「今天」換成實際發送日期，如需要。

---

大家好，我把法訊雷達的分工和第一階段待辦整理好了，請先看 [團隊分工與 GitHub 協作](https://github.com/yang-yang1211/law_tec/blob/docs/team-workplan-kickoff/docs/團隊分工與GitHub協作.md)，再到自己負責的 GitHub Issue 留言認領。分工用 A–E 代號，不使用職稱；目前 GitHub 帳號還沒對應，所以先用留言認領，確認帳號後再設定 assignee。

**第一階段目標：** 先做出「選關注 → 看個人化法訊 → 查官方來源 → 問答附引用 → LINE 個人通知」的端到端展示。首頁目前是互動式介面原型，接下來要讓各模組共用同一筆法訊資料。

| 成員 | 先做的事 | Issue |
|---|---|---|
| A（我） | 定第一版使用情境與共用資料欄位，安排整合節點和提案文件 | [#1](https://github.com/yang-yang1211/law_tec/issues/1)、[#7](https://github.com/yang-yang1211/law_tec/issues/7)、[#9](https://github.com/yang-yang1211/law_tec/issues/9)、[#10](https://github.com/yang-yang1211/law_tec/issues/10) |
| B | 做個人化 feed 與排序：推薦／追蹤／最新、推薦理由 | [#2](https://github.com/yang-yang1211/law_tec/issues/2) |
| C | 核對官方資料，建立引用問答與無依據時的拒答 | [#3](https://github.com/yang-yang1211/law_tec/issues/3)、[#4](https://github.com/yang-yang1211/law_tec/issues/4) |
| D | 完成 LINE 連結與通知流程，先用示意資料做匹配／不匹配情境 | [#5](https://github.com/yang-yang1211/law_tec/issues/5)、[#6](https://github.com/yang-yang1211/law_tec/issues/6) |
| E | 協助 C 複核來源，整理至少 10 個手動驗收情境和 Demo 素材 | [#3](https://github.com/yang-yang1211/law_tec/issues/3)、[#8](https://github.com/yang-yang1211/law_tec/issues/8)、[#9](https://github.com/yang-yang1211/law_tec/issues/9)、[#10](https://github.com/yang-yang1211/law_tec/issues/10) |

B、C、D 各自負責一個核心模組，也請在交付時附上簡短說明：資料怎麼進來、核心判斷怎麼做、可能失敗在哪、如何驗收，並準備 5–10 分鐘示範，讓大家都能理解和 Review。

**今天請先完成：**

1. 到自己的 Issue 留言認領，寫上預計交付日期和需要的協助。
2. 先讀 #1 的共用資料欄位；A 定稿後，B、C、D 依同一格式開始，不要各自發明欄位。
3. 每天在自己的 Issue 更新「昨天完成／今天要完成／卡住需要誰協助」。

內部節點與驗收條件都整理在 Issue；競賽正式繳件日期與規格以 repo 裡的簡章及主辦單位公告為準。所有示例資料要標明「示意」或附上已核對的官方來源；LINE 真實推播只用團隊確認的測試帳號，不要把 token 或 secret 放進 GitHub。
