# 推薦排序規則 v1

> 對應 Issue #2。程式：`prototype/recommendation.js`；資料格式依 [資料契約 v1.0.0](資料契約.md)。
> 本文件例子使用 `prototype/demo-items.js` 的虛構示意資料，不是法律資訊。

## 輸入

- **法訊**：資料契約 v1.0.0 的 `NewsItem[]`
- **使用者偏好**：`{ topicTags: [...], audienceTags: [...] }`
- **基準時間 `now`**：由呼叫端傳入，排序函式本身不讀取目前時間，所以相同輸入一定得到相同結果

## 計分公式

| 條件 | 分數 | 說明 |
|---|---:|---|
| 法訊 `topicTags` 至少命中一個使用者議題 | +40 | 命中多個不累加 |
| 法訊 `audienceTags` 至少命中一個使用者身分 | +30 | 命中多個不累加 |
| 有效時間在 7 日內 | +20 | 有效時間 = `updatedAt`，缺少時用 `publishedAt` |
| 有效時間在 8–30 日 | +10 | 天數無條件捨去，例如 7.9 天算 7 天 |
| 有效時間超過 30 日或日期未知 | 0 | |
| `notificationLevel = important` 且 `verificationStatus = verified` | +10 | 兩個條件都要成立 |

**總分 = 議題分 + 身分分 + 新近度分 + 重要度分**，最高 100 分。

法案狀態（`billStage`、`legalEffect`）**不計分**，只在卡片上照資料原樣顯示。

## 排序順序

1. 總分高到低
2. 同分：有效時間新到舊，沒有日期的排後面
3. 再同：依 `id` 字母順序

## 前五則主題分散

- 主題 = `topicTags` 的第一個值
- 在前五則中，如果下一則會造成**連續三則同主題**，就往後找第一則不同主題的法訊替補
- 替補的分數如果比原本那則**低超過 10 分**，就不換，保留原排序

## 三個檢視

| 檢視 | 篩選 | 排序 | 推薦理由 |
|---|---|---|---|
| 為你推薦 | 全部 | 上述計分與主題分散 | 列出實際加分的項目 |
| 我追蹤的 | 至少命中一個議題或身分標籤 | 有效時間新到舊 | 列出命中的標籤 |
| 最新消息 | 全部 | 有效時間新到舊，沒有日期排最後 | 不顯示（不做個人化） |

搜尋會在目前檢視中比對標題、摘要和標籤。

## 「示意／待核」標示

`verificationStatus` 不是 `verified`，或 `source.url` 為空時，卡片顯示「示意／待核：尚未完成官方來源核對」，詳情頁註明不可當作已核實法訊。

## 算分例子

條件：使用者關注議題「租屋權益、學生打工」、身分「租屋族、學生」；基準時間 2026-11-27 12:00（UTC+8）。

### 例子 1：重要但未核對，不加重要度分

`demo-b-rent-001`：議題「租屋權益」、身分「租屋族」、`updatedAt` 2026-11-26、`notificationLevel = important`、`verificationStatus = pending`

| 項目 | 分數 |
|---|---:|
| 議題命中「租屋權益」 | +40 |
| 身分命中「租屋族」 | +30 |
| 1 日前更新（7 日內） | +20 |
| important 但尚未 verified | 0 |
| **總分** | **90** |

### 例子 2：沒有 updatedAt，改用 publishedAt

`demo-b-work-001`：議題「學生打工」、身分「學生」、`updatedAt = null`、`publishedAt` 2026-11-10

| 項目 | 分數 |
|---|---:|
| 議題命中「學生打工」 | +40 |
| 身分命中「學生」 | +30 |
| 改用 publishedAt，17 日前（8–30 日） | +10 |
| **總分** | **80** |

### 例子 3：沒有任何日期

`demo-b-nodate-001`：議題「學生打工」、身分「學生」、兩個日期都是 `null`

| 項目 | 分數 |
|---|---:|
| 議題命中「學生打工」 | +40 |
| 身分命中「學生」 | +30 |
| 日期未知 | 0 |
| **總分** | **70** |

### 例子 4：標籤都沒命中

`demo-b-labor-001`：議題「勞動保障」、沒有身分標籤、`publishedAt` 2026-11-27

| 項目 | 分數 |
|---|---:|
| 議題、身分都沒命中 | 0 |
| 當日發布（7 日內） | +20 |
| **總分** | **20** |

這則在「我追蹤的」會被排除；但它最新，所以在「最新消息」排第一。

### 例子 5：主題分散

「為你推薦」實際排序結果：

| 名次 | id | 主題 | 分數 |
|---:|---|---|---:|
| 1 | demo-b-rent-001 | 租屋權益 | 90 |
| 2 | demo-b-rent-002 | 租屋權益 | 90 |
| 3 | demo-b-work-001 | 學生打工 | 80 |
| 4 | demo-b-rent-003 | 租屋權益 | 90 |
| 5 | demo-b-nodate-001 | 學生打工 | 70 |
| 6 | demo-b-labor-001 | 勞動保障 | 20 |

只看分數的話，第 3 名應該是 90 分的 `rent-003`，但這樣前三則會連續都是「租屋權益」。`work-001` 只低 10 分，沒有超過 10 分，所以把它換到第 3 名。

## 驗收情境

| 情境 | 步驟 | 預期結果 |
|---|---|---|
| 標籤命中與主題分散 | 預設關注，開啟「為你推薦」 | 排序如例子 5，每張卡片顯示對應的推薦理由 |
| 追蹤無匹配排除 | 切到「我追蹤的」 | 共 5 則，不含 `demo-b-labor-001` |
| 最新排序與日期缺漏 | 切到「最新消息」 | `labor-001` 第一，`nodate-001` 最後 |
| 搜尋無結果 | 搜尋「不存在」 | 顯示「找不到符合…」與「清除搜尋」 |
| 追蹤清單為空 | 取消全部關注標籤後開「我追蹤的」 | 顯示「目前沒有符合你追蹤標籤的法訊」與「編輯關注」 |
| 390px 窄螢幕 | 開發者工具設定寬度 390 | 卡片可閱讀，首頁搜尋框可使用 |

用 Node 檢查排序：

```bash
node prototype/try-ranking.js
```

## 已知限制

1. **目前使用示意資料**：首頁讀取 `prototype/demo-items.js`（全部為 `pending` 的虛構資料），尚未讀取共用 fixture。原因是直接開啟 HTML（`file://`）時瀏覽器不允許讀取 JSON；C 提供核對資料後，需改用本機伺服器讀取 `data/fixtures/news-items.v1.json`。
2. **標籤必須完全相同才算命中**：沒有處理同義詞，例如「租屋」不會命中「租屋權益」。
3. **主題只看第一個 `topicTags`**：同時有多個議題的法訊，主題分散只依第一個判斷。
4. **未使用互動回饋**：計畫書提到的收藏、「少推薦這類」尚未納入計分。
5. **關注選項包含 v1 詞彙以外的標籤**：如「消費者保護」，目前沒有法訊使用這些標籤，所以不會命中。
6. **時間依使用者電腦**：網頁以瀏覽器目前時間計算新近度；電腦時間錯誤會影響分數。未來時間視為 0 日前。
